# ผลแก้ไขจากการตรวจ GECC — 1 พฤศจิกายน 2569

แก้โค้ดที่ยืนยันสาเหตุได้และเตรียมชุดอัปเดต PHP สำหรับระบบเดิม ยังไม่ได้อัปโหลดหรือเปลี่ยนข้อมูลบัญชีบน Production จึงยังไม่รับรองความพร้อม 100% ก่อนตรวจรับหลัง deploy

## การแก้ไข

- ตัวติดตั้งส่ง schema SQL ทั้งชุด ไม่แยกตาม semicolon ที่อยู่ใน comment จึงติดตั้ง MariaDB ใหม่ได้จริง
- รายงานกายภาพแยกยังไม่ตรวจ ตรวจบางส่วน และผ่านครบ ป้องกันข้อความผ่านครบในชุดข้อมูลว่าง ทั้งภาพรวมและรายข้อ
- หัวข้อหน้าประเมินมีพื้นที่อ่านได้บนมือถือ/แท็บเล็ต ปุ่มเปลี่ยนหน่วยมีชื่อสำหรับโปรแกรมอ่านหน้าจอ หัวการ์ดใช้คู่สีของธีมสว่าง/มืด
- หน้าบังคับเปลี่ยนรหัสปิดด้วย Escape/ฉากหลังไม่ได้ มีทางออกจากระบบ และห้ามบันทึกก่อนตั้งรหัสสำเร็จ
- API ตรวจ Content-Type และ JSON ทั้ง HTTP สำเร็จและผิดพลาด แสดงข้อความไทยเมื่อพบ HTML challenge/JSON เสีย เก็บร่างและระงับการส่งซ้ำเมื่อยังไม่ทราบผล write
- เพิ่มช่องตั้ง HTTPS URL แบบสำรวจผ่านตัวแก้เนื้อหา ตรวจทั้งหน้าเว็บและ backend ไม่รับ URL ที่ฝัง user/password หรือ scheme อันตราย
- Gallery โหลดผิดพลาดมีปุ่มลองใหม่
- เพิ่ม CLI ตรวจบัญชี เตรียมบัญชีหน่วยที่ขาด และปรับกลุ่ม MENTOR หลังยืนยันตัวบุคคล คงรหัสผ่าน ID และประวัติเดิม ยกเลิก session เมื่อปรับกลุ่ม และมี preview/revision guard
- ชุด deploy ไม่รวม private account bundles ที่สร้างขึ้นภายหลัง พร้อมคู่มือและตัวอย่างที่เริ่มด้วยการยืนยันสิทธิ์เป็น false

## ผลทดสอบ

- `npm test`: 64 tests, ผ่าน 63, ข้าม 1, ล้มเหลว 0 ข้อที่ข้ามเทียบภาพต้นฉบับภายนอก repository ซึ่งไม่มีในเครื่อง ชุดภาพ 42 ภาพใน repository ผ่านการตรวจรายการ
- `npm run test:content`: ผ่าน Gallery, roster, content editor, public filters และ responsive themes
- `npm run test:php`: ผ่าน 20 กลุ่มบน PHP/MariaDB รวม 52 สถานะ axe ไม่พบ violations ตามชุดกฎที่ทดสอบ และไม่มี JavaScript page errors
- ทดสอบ regression เพิ่มสำหรับข้อมูลกายภาพว่าง/บางส่วน, HTML/JSON เสียทั้งสถานะ 200 และ 500/503 โดยไม่ replay write, URL แบบสำรวจ, การสร้างบัญชีเฉพาะที่ขาด, revision เก่า, รันซ้ำ, ชื่อบัญชีชน, ปรับกลุ่มโดยคง identity/password และเพิกถอน session
- ตรวจหน้าประเมินที่ 360/390/768px เพิ่ม assertion พื้นที่ชื่อหน่วยมากกว่า 200px และชื่อปุ่มเปลี่ยนหน่วย
- ผู้ตรวจแยกตรวจ source ตาม checklist ไม่พบประเด็นที่ต้องแก้ค้างในขอบเขตนี้ ภาพหลักฐาน local demo อยู่ที่ `artifacts/audit-remediation-mobile-390.png`
- strict static premium audit มี heuristic ที่ยังไม่ผ่าน และสแกนสำเนา release/test เก่าใน var ด้วย จึงไม่ใช้เป็นหลักฐานรับรองว่าผ่านทั้งหมด ผล runtime/axe และการตรวจหน้าจอเป็นหลักฐานแยกต่างหาก

## งานบนเซิร์ฟเวอร์ที่ยังค้าง

1. สำรองฐานข้อมูล ไฟล์จริง และ config แล้วอัปโหลด public/ กับ gecc-private/ ตาม `SERVER-UPDATE-AUDIT-2026-11-01-TH.md` ห้าม import seed หรือเปิด installer ซ้ำ
2. รัน CLI check แล้วสร้างเฉพาะหน่วย 000029–000032 ที่ยังขาดตามข้อมูลปัจจุบัน รหัสใหม่อยู่ใน private directory และต้องส่งให้เจ้าของบัญชีเป็นการส่วนตัว
3. ตรวจชื่อและกลุ่ม MENTOR ทั้ง 24 คนกับผู้ถือบัญชีจริง พบอย่างน้อย 9 จุดไม่ตรงใน audit เดิม ตัวอย่าง manifest มีเพียงสองคู่ ไม่ใช่รายการแก้ครบ ห้ามเดาตัวบุคคลหรือใช้บัญชีคนเก่าให้คนใหม่
4. ยืนยันการมอบหมายและเปิดบัญชีที่ปรึกษาแยก 6 คนด้วย advisor-accounts.php ตามคู่มือเดิม ไม่เพิ่มสิทธิ์จากการอัปโหลดโค้ดอัตโนมัติ
5. ใส่ URL แบบสำรวจจริง ตรวจ bot protection กับโฮสต์ และทำ UAT บน staging ครบวงจรส่ง/ตรวจ/แก้/ล็อก/เปิดใหม่ แนบไฟล์ สองผู้ใช้พร้อมกัน และกู้คืน backup
6. ทดสอบซ้ำบน Production หลังอัปโหลด ตรวจทุกบัญชีที่ปรับ ไม่มีการเขียนข้อมูลทดสอบลงฐานจริงในรอบแก้โค้ดนี้

รายงานนี้ไม่รวมรหัสผ่าน เอกสาร credential หรือข้อมูลการประเมินจริง
